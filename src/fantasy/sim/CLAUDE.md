# src/fantasy/sim: simulation logic

Pure logic. Stages and the API read tables and hand the values in. The `simulate` stage is described in `stages/CLAUDE.md`.

- `sim/league_data.py`: `load_league_data(league, strict, data_dir)` builds the `LeagueData` class (defined in `sim/odds.py`) from the tables. `stages/simulate.py` (strict) and the API (lenient) call it. Its parts: `sim/league_projections.py` (layered projections, kicker and defense inputs) and `sim/league_checks.py` (what is dropped or cannot be modelled).
- `LeagueData.kd_slot` holds those values, keyed by (kind, roster id, week). `kd_slot_mean` in `sim/odds.py` reads it, falling back to the league mean.
- `kd_slot_projections` (in `league_projections.py`): each team's K and DEF slots use its best rostered unit's projection, with the league mean where a team has none, and the league-wide spread.
- `sim/bracket.py`: pure bracket engine (`template(playoff_teams, round_type)` for 4, 6, 8; `from_rows`, `resolve`, `round_weeks`, `playoff_weeks`, `round_of_week`, `round_type_of`). `shape_problem` is the one gate for what the model can fit (sizes 4/6/8, round types 0/1/2, last playoff week 17, no reseeding or divisions yet); `season.format_problem`, `league_checks.check_league_shape` and `auth/my_leagues` all use it. A two-week round is decided by the sum of both weeks. `LeagueData.playoff_teams`/`round_type` set the number of simulated playoff weeks. `simulate_season` uses it; real `playoff_brackets` rows count only when `current_week >= playoff_start`, then they also fix the seeds. `build_inputs` simulates from `min(current_week, playoff_start)`; played playoff weeks use `LeagueData.realized` points with no noise. Standings count regular-season weeks only. `simulate` writes per-round odds to `sim_bracket`. New draws must be keyed by (seed, roster, week).
- `sim/blend.py`: current week is the equal mean of ours and each `blend_sources` entry the player has. The next three weeks use ours and Sleeper. Where Sleeper is a row's only other source, it gets `SLEEPER_WEIGHT` (0.5, so the same as the equal mean until issue #40 retests it). `blend_all` takes the sources by name (`{"sleeper": ..., "props": ...}`).
- Injury uses the availability model for a flagged player's next game. Season odds also produce `sim_conditional` (what-ifs) and `sim_win_need` (display only: my playoff odds by wins in the next four games, from the same draws).
- Point-valued effects are measured in the reference league (lowest id) and scaled per league (`sim/scoring_scale.py`). Add a new point-valued effect to a `*_POINT_KINDS` set in `sim/league_projections.py` (`OUTLOOK_POINT_KINDS`). Otherwise YinzBurgh (0.5 PPR) is overstated.
- `sim/moves.py` is a facade that keeps `moves.<name>` working. The logic is in `roster` (`Valuer`, free agents), `waivers`, `trades` (apply, evaluate, search), `trade_labels` and `needs`. New code imports those modules directly.
